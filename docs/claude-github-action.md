# Guides from Claude Code in GitHub Actions

Omakaze can have a guide written for every pull request on a **Claude subscription** (Pro or Max) instead of an Anthropic API key. Claude Code runs in GitHub Actions through the official [Claude Code GitHub Action](https://github.com/anthropics/claude-code-action), signs in with a token from your subscription, and writes the guide through Omakaze's [MCP server](mcp.md), the same way it does when you ask it to on your own computer.

Omakaze makes no model requests itself, so the workspace needs no [AI provider](ai.md). Usage counts toward the plan of the person whose token the workflow uses.

## Why a workflow and not a provider

The built-in AI lets members use their [ChatGPT plan](ai.md#chatgpt-plans) because OpenAI offers a sign-in for open-source apps to send requests on a user's plan. Anthropic does not offer one for Claude plans: subscription tokens are for Claude Code itself, and other apps have to use an API key. The supported way to use a Claude subscription for automation is to run Claude Code, which is what this workflow does.

## Setup

1. **Claude token.** On your computer, with Claude Code installed and a Pro or Max plan, run:

   ```sh
   claude setup-token
   ```

   It opens a browser to sign in and prints a long-lived OAuth token. Store it as the repository (or organization) secret `CLAUDE_CODE_OAUTH_TOKEN`.

2. **Omakaze token.** Create an API token (for example named `Claude Code (GitHub Actions)`) in **Settings → API tokens & MCP** of the workspace that follows the repository, and store it as the secret `OMAKAZE_TOKEN`. Guides are created as the member who owns the token; a token of an admin or owner can also add the repository to the workspace if it is not followed yet (see [mcp.md](mcp.md#repositories-and-permissions)).

3. **Workflow.** Copy the workflow from **Automate with Claude Code** in **Settings → API tokens & MCP**, which has your instance's URL filled in, into `.github/workflows/omakaze-guide.yml`. It is the same as the one below with `<APP_URL>` replaced.

The Omakaze instance must be reachable from GitHub's runners (or from your self-hosted runners).

```yaml
name: Omakaze guide (Claude)

on:
  pull_request:
    types: [opened, reopened, synchronize, ready_for_review]

concurrency:
  group: omakaze-guide-${{ github.event.pull_request.number }}
  cancel-in-progress: true

permissions:
  contents: read
  pull-requests: read

jobs:
  omakaze-guide:
    if: github.event.pull_request.draft == false && github.event.pull_request.head.repo.full_name == github.repository
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 1

      - name: Configure the Omakaze MCP server
        env:
          OMAKAZE_TOKEN: ${{ secrets.OMAKAZE_TOKEN }}
        run: |
          jq -n --arg url "<APP_URL>/api/mcp" --arg auth "Bearer $OMAKAZE_TOKEN" \
            '{mcpServers: {omakaze: {type: "http", url: $url, headers: {Authorization: $auth}}}}' \
            > "$RUNNER_TEMP/omakaze-mcp.json"

      - name: Write the guide with Claude Code
        uses: anthropics/claude-code-action@v1
        with:
          claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
          github_token: ${{ secrets.GITHUB_TOKEN }}
          prompt: |
            Create a guided PR for ${{ github.event.pull_request.html_url }} using the Omakaze MCP.
            Use head_sha ${{ github.event.pull_request.head.sha }}. Only write the guide: do not
            post comments or reviews, and do not change any files in this repository.
          claude_args: |
            --mcp-config ${{ runner.temp }}/omakaze-mcp.json
            --allowedTools mcp__omakaze__whoami,mcp__omakaze__get_pull_request,mcp__omakaze__get_diff,mcp__omakaze__read_file,mcp__omakaze__list_review_comments,mcp__omakaze__create_guide,mcp__omakaze__start_guide,mcp__omakaze__add_section,mcp__omakaze__update_section,mcp__omakaze__delete_section,mcp__omakaze__reorder_sections,mcp__omakaze__update_guide,mcp__omakaze__get_guide,mcp__omakaze__check_coverage,mcp__omakaze__finish_guide
            --disallowedTools Bash,Edit,Write,NotebookEdit,WebFetch,WebSearch
```

The workflow is generated by `claudeWorkflow` in `src/lib/prompts.ts`; `tests/lib.test.ts` checks that every allowed tool exists.

## What the workflow does

- **When.** On `opened`, `reopened`, `synchronize` (new commits) and `ready_for_review`. Drafts are skipped. A new push cancels a run that is still writing the guide for an older commit; the guide that run started is marked as [abandoned](ai.md#abandoned-guides) after 60 minutes, and the new run writes a new version.
- **MCP server.** The first step writes an MCP configuration with the instance URL and the `Authorization` header to the runner's temporary directory, so the token is not part of the command line.
- **Prompt.** The same prompt as **Copy agent prompt**, with the head commit, so the guide is written for the commit the workflow ran on. The server's instructions give Claude the authoring guidelines, the diff format and the [guide template](ai.md#guide-templates) of the repository.
- **Tools.** Claude may read the pull request and the repository and use the guide tools of the MCP server. The review tools (`reply_to_review_comment`, `post_review_comment`, `resolve_review_thread`, `submit_review`, `post_pr_comment`) and `upload_asset` are not allowed, and neither are shell commands, file edits and web requests, so text in a pull request cannot make the workflow post to GitHub, change the repository or fetch URLs. The workflow's `GITHUB_TOKEN` is read-only.
- **Model.** Claude Code's default model for your plan. Add `--model <name>` to `claude_args` to pick another.

The guide is recorded as created over MCP, with the API token's name as its author (so name the token something like `Claude Code (GitHub Actions)`), and counts as an MCP agent guide in **Insights**. **Post a summary comment on GitHub** in **Settings → Automation** still posts its comment when the guide is published.

## Notes

- **Forks.** Workflows for pull requests from forks get no secrets, so the job is skipped for them (`head.repo.full_name == github.repository`). Do not switch to `pull_request_target` to work around this: it would run with your secrets on code and text from the fork.
- **Built-in automation.** Leave **Create a guide for every new pull request** in **Settings → Automation** off for repositories that use this workflow, or every pull request gets two guides.
- **AI code reviewers.** The job is named `omakaze-guide`, so Omakaze does not mistake it for [Claude Code Review](ai-reviewers.md) (`claude-review`). If the repository also runs a Claude review workflow, the guide does not wait for it. To have Claude include the review's findings, run this workflow after the review, for example with `workflow_run`, or rely on the built-in AI, which waits for reviewers.
- **Usage.** Each run is a full Claude Code session on the token owner's plan and counts toward its usage limits, shared with their other use of Claude. Large pull requests use more. Tokens from `claude setup-token` last a year; run it again and update the secret when it expires.
- **Several repositories.** Store `CLAUDE_CODE_OAUTH_TOKEN` and `OMAKAZE_TOKEN` as organization secrets and add the workflow to each repository.
- **Writing guides on demand.** Without a workflow, ask Claude Code on your computer: `Create a guided PR for <PR URL> using the Omakaze MCP.` See [Connect an agent](../README.md#connect-an-agent).
